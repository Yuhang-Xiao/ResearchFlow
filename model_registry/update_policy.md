# Model Registry Update Policy

The registry can be updated automatically for low-risk local additions such as new task entries, missing metric maps, repair strategies, and documentation stubs. It must not install dependencies, run external code, write Zotero SQLite, or copy licensed code without user authorization.

Update triggers include new task types, repeated gate failures, missing metrics, repeated model failures, new literature evidence, strong GitHub/HF/OpenML engineering references, and user feedback that a product was incomplete.
